# 故障排查

排查原则：**先看脚本给出的错误行**（脚本已把平台返回的错误翻译成中性描述并脱敏），
再对照本表处理。不要向用户输出堆栈、内部域名或原始上游错误。

---

## 1. 配置与凭据

> 本节的命令示例用 `python3` 作**占位**；先确认本机实际可用名（`python3` / `python` / `py -3`），
> 详见 `SKILL.md` 的「运行环境」一节。

| 现象 | 原因 | 处理 |
|---|---|---|
| 命令像跑了但**没任何输出、也不报错** | **Windows 特有**：`python3` 被 Microsoft Store 的"应用安装程序"占位符拦下（退出码非 0） | 换用 `python` 或 `py -3` 重跑，**不要**据此判断脚本损坏。注意：这只影响你**手敲**命令；脚本自身输出的提示用的是解释器绝对路径，不受此影响。另：`py` 启动器不是标配，本机可能根本没有 `py` 命令 |
| `command not found` / `不是内部或外部命令` | 本机没有 Python，或安装时未勾选加入 PATH | 按 `references/host-compatibility.md` §2 的六步处理（探测 → 告知 → **征得用户同意** → 安装 → 重启 agent → 重试）；**不要**改用手写 `curl` 绕开脚本 |
| 命令需用户逐次批准 / 被拒绝执行 | 客户端权限策略 | 把要执行的**脚本绝对路径**告知用户，由用户决定是否允许；不要反复重试或换命令绕过。详见 `references/host-compatibility.md` §1 |
| 请求超时 / 提示需要网络权限 | 客户端沙箱默认禁网（部分客户端如此） | **本 skill 必须出网**（调生成接口）。禁网环境下整体不可用，需用户自行开启网络；agent 无法绕过。详见 `references/host-compatibility.md` §3.1 |
| agent 里看不到本 skill | 它没有被放进**该 agent 读取的**技能目录 | 每个 agent 的技能根不同，装错位置 = 装完了读不到。用分发工具的 `install`（`--target auto` 会按当前 agent 选择），装完看它的**可见性自检**输出；详见 `references/host-compatibility.md` §4 |
| 提示"已安装且一致"，但 agent 始终发现不了 | 装到了别的 agent 的技能根（历史版本会固定装到 `~/.codebuddy/skills`） | 重新 `install`（新版会选当前 agent 的技能根），或显式 `install --target agents`（DSH 等通用 agents 根）后重新加载技能列表 |
| skill 内容已更新但 agent 行为没变 | 客户端加载的是旧副本 | 用最新版本覆盖技能目录里的副本（`install` 是增量的），再让 agent 重新加载技能列表 |
| 出现 ASCII logo + "尚未配置 API Key" | 本机没有保存 Key | **把引导块原样展示给用户** → 用户到 `https://noova.vip/api_control`（备用 `https://noova.live/api_control`；登录 → 「API 管理」→「创建 API Key」→ 复制完整 Key）创建 → 用户把 Key 粘贴过来 → `noova_key.py setup --stdin`（或 `setup "<粘贴内容>"`） |
| 用户只给了地址没给 Key | 只想先指定 API 地址 | `setup` 会先落盘地址并返回 `exit=1`，此时继续向用户索要 `sk-` 开头的 Key。**单独用 `--base-url <地址>` 也走这条路**（不再报 exit=2） |
| `xxx 是本机 / 内网 / 开发环境地址，只有当前这台机器能访问它` | 粘贴内容里带了本地开发地址（`localhost` / `127.0.0.1` / `192.168.*` / `dev.*` …） | **不要改成"强写"**：本 skill 只对接线上部署域名，直接用 `https://noova.vip` 重跑 `setup`；若确实要自建线上域名，用**显式** `--base-url <你的线上域名>`。脚本拒绝时会说明"**Key 未离开本机**"——确实没有发过请求 |
| 提示"已忽略文本中的地址：https://…" | 粘贴内容里带了非官方域名的链接（常见于从网页复制 Key 时连带复制了文档链接） | 这是**保护**：基础地址只认 `--base-url`、JSON 的 `base_url` 字段，或与官方域名同域的地址。若那个地址确实是你要的，用 `--base-url` 显式指定 |
| `verify` 返回 exit=2 并提示地址不是线上域名 | `NOOVA_BASE_URL` 或历史配置指向本机/内网 | `noova_key.py base https://noova.vip`（或备用 `https://noova.live`）改回。**守卫在发请求前生效，Key 没有被发出去** |
| 主域名被网络策略阻断（无法访问 `noova.vip`） | 换用官方备用域名即可 | `noova_key.py base https://noova.live`；两个域名都承载同一套对外 API 与同一批账号（Key 通用）。**不要**自行搭代理或改本地 hosts |
| `doctor` 报 `[!!] 基础地址为线上域名` | 配置或环境变量里的地址不是线上域名 | `noova_key.py base https://noova.vip` 改回；检查是否设过 `NOOVA_BASE_URL` |
| `doctor` 报 `[!!] 配置文件可解析` | 配置文件不是合法 JSON（中断写入或手工编辑引入语法错误）——**其中的配置全部未生效** | 按提示删掉该文件后重新 `setup`；脚本写盘是原子的，正常中断不会产生这种文件 |
| 生成请求报"地址不是线上部署域名" | 历史配置遗留了本机地址 | 同上；只补 Key 时 `setup` 也会**自动**把这种遗留地址替换为线上域名 |
| `认证未通过 / API Key 无效或已停用` | Key 错误、被停用或已删除 | `setup` 会**拒绝写入**并提示重新获取；不要反复重试；`--force` 可强写（一般不要用） |
| 明明粘贴了正确的 Key，却被报"API Key 无效" | 粘贴文本里同时含 `token=` / `secret=` 之类的其它字段，旧版解析器会优先取它 | 已修复（v1.5.0）：现在**优先按 `sk-` 前缀**认 Key。若仍遇到，用 `setup --api-key sk-…` 只传 Key |
| 提示"未能判定（离线或服务异常）" | 校验请求没成功（网络/服务异常） | Key 已落盘；稍后用 `noova_key.py verify` 复查，不必重新配置 |
| 换了机器/换了 agent 工具后又提示配置 | Key 存在本机用户目录，不随工具迁移 | 在新环境重新 `setup` 同一个 Key（或新建） |
| 想临时指定不同 Key | 需要切换账号 | 用环境变量 `NOOVA_API_KEY` 覆盖，或重新 `setup` 覆盖后 `clear` |
| 不知道"还差什么" | — | `noova_key.py doctor` 逐项自检（9 项：Python / 解释器路径 / 依赖脚本 / 配置目录可写 / 配置文件可解析 / Key 状态 / 地址是否为线上域名 / 地址可达性 / Key 有效性） |
| 想知道 Key 到底存在哪个文件 | 路径随用户 / 系统 / 安装位置而变 | 引导块与 `doctor` 都会打印**解析后的实际路径**，直接引用即可；**不要照抄本文档示例路径，也不要自己拼** |
| 设了 `NOOVA_CONFIG_DIR` 但 Key 好像写到了别处 | — | 该覆盖项**读写两侧都优先**，不会因为家目录存在旧配置而改道；若该目录建不出来，脚本**直接报错**而不是偷偷写到别处（v1.5.0） |
| `clear` 说清除了，但请求仍然成功 | 历史上只清了最高优先级的那个配置文件 | 已修复（v1.5.0）：`clear` 现在清除**全部**配置来源，并列出被改写的文件；环境变量 `NOOVA_API_KEY` 需用户自行清理（脚本会提示） |

提示：`noova_key.py status --json` 提供机器可读状态
（`configured` / `key_prefix` / `key_source` / `base_url` / `config_file` /
`corrupt_config_files`），供排查用。
**它不是必需的前置步骤**——直接生成即可，缺 Key 时脚本会自行拦截并打印引导块。

> ⚠️ **不要用模型清单接口判断 Key 是否有效**：`/api/v1/gateway/models`、`/v1/models` 都**不应该**
> 被拿来判定 Key（`/v1/models` 2026-10-06 起已改为需要有效 Key；`/api/v1/gateway/models`
> 自 2026-10-07 起需**登录 token**、属对内控制台链路，本 skill 一律不访问）。
> 唯一可用于校验的是 `POST /api/v1/gateway/validate-key`
> （恒 200，看 `data.valid`），回退方案是 `GET /api/v1/credit`（无效 Key → 401）。
> 脚本的 `verify` / `doctor` / `setup` 已按此实现。

## 2. 网络与访问

| 现象 | 原因 | 处理 |
|---|---|---|
| `请求被网络策略拦截（客户端标识被拒绝）`（响应体含一个厂商特有的边缘拦截错误码） | 边缘网络策略拦截了"已知自动化客户端的默认标识" | 脚本已显式携带标准客户端标识；若仍出现，说明该网络环境被额外限制，请如实反馈现象，**不要**改造成伪装浏览器的做法（此条针对**平台 API**；第三方图床通道所需的请求头由脚本固定携带，见 `api-contracts.md` 的素材上传章节，两者不是一回事） |
| `网络连接失败` / `请求超时` | 本机网络或链路问题 | 稍后重试；必要时增大 `--timeout` |
| `已配置 Key` 但请求仍然 401 | Key 与当前基础地址不匹配（例如切到了另一个环境） | 先 `noova_key.py base` 查看当前基础地址，确认是否与 Key 所属环境一致 |

## 3. 请求与响应

| 现象 | 原因 | 处理 |
|---|---|---|
| `模型「xxx」有必填参数未提供：…` | 该模型的参数契约把某些参数标为必填（参考素材 / 时长 / 比例等），而命令里没给 | 按报错里 `·` 开头的提示逐项补齐：参考素材用 `--ref-image` / `--ref-video` / `--ref-audio`，其余用 `--param 名称=值`。**注意脚本根本没发出请求**，反复重试同一条命令不会有不同结果 |
| `HTTP 400 请求体缺少 model` | 未指定模型 | 脚本默认会自动选模型；若显式传了空 `--model` 请去掉 |
| `HTTP 400 参数错误` | 参数值非法 / 参数名不在该模型参数契约 | 用 `params --code <编码>` 核对参数名与取值（取值必须在 `values` 里，数值必须在 `min`~`max` 内） |
| 请求成功但效果没变化 | 传了模型不认识的参数名（会被静默忽略） | 核对参数名拼写与大小写 |
| `未找到模型「xxx」` | 模型编码错误、已下线，或**非对外可见状态**（测试 / 废弃等） | 用 `models` 重新拉取清单；不要用记忆里的编码 |
| `当前状态：维护中（暂不可调用）` | 模型维护中（已对外展示，但不可调用） | 换用同类型其它模型，或告知用户稍后重试；展示清单时要注明它是「维护中」 |
| `当前平台没有可用的「audio」模型` | 该类型当前无上线模型 | 如实告知用户"平台当前无可用音频模型"，**不要编造模型编码** |
| `HTTP 403 无权调用该模型` | 该 Key 没有该模型权限 | 告知用户到官网确认 Key 的模型权限 |
| `HTTP 402 积分不足` | 余额不足 | 引导充值；可用 `credit` 查询当前余额 |
| 多结果只展示了一个 | 输出被截断 | 一次生成可能有多张：默认输出会把**全部**结果编号列出（`1. … 2. …`），逐条交付给用户 |

## 4. 限流与并发

| 现象 | 原因 | 处理 |
|---|---|---|
| `HTTP 429 请求过于频繁` | 生成请求被限流（按来源 IP，60 次/分钟） | 按 `Retry-After` 等待；脚本对**查询类**请求会自动重试有限次，**创建任务/文本生成这类计费请求不会自动重试**（避免重复扣费），需要时由你显式重跑一次命令；批量任务请降低并发 |
| `HTTP 503 平台繁忙（配额已满）` | 账户分钟生成配额用尽（默认 80/min，VIP 200/min） | 等 `Retry-After`（通常 60s）后重试；不要连环重试 |
| `HTTP 502 / 500` | 服务或上游暂时异常 | 稍后重试；向用户转述为"服务暂时不可用" |
| `网络传输中断（IncompleteRead）` | 响应被截断 / 连接被重置 | 重试；若持续出现，检查代理与网络设备。脚本已把这类异常翻译成一行中性提示，**不会**打印堆栈 |
| 命令输出像崩溃但只有一行"未预期的内部错误" | 兜底保护生效（正常情况下不该出现） | 重试一次；持续出现时把该现象反馈给维护者。需要堆栈排障时设 `NOOVA_DEBUG=1` 再跑一次（**仅开发环境**） |

## 5. 长任务

| 现象 | 原因 | 处理 |
|---|---|---|
| 视频/大图等待超时（脚本打印任务 ID） | 本地等待上限到了，任务仍在进行 | **不是失败**：`wait --id <任务ID> --max-wait 1800` 续等，或 `task --id <任务ID>` 查一次 |
| 想先拿到任务 ID 稍后再取 | 需要非阻塞 | 生成时加 `--no-wait`，记录返回的任务 ID |
| `任务不存在或无权访问`（404） | 任务 ID 属于其它 Key 的账户，或 ID 写错 | 用创建任务时打印的 ID；不要跨账号查询 |

## 6. 上传素材

| 现象 | 原因 | 处理 |
|---|---|---|
| 参考图/首帧上传失败 | 文件不存在/为空；或所通道临时不可用 | 检查文件；默认会**自动降级**到下一通道，看逐通道失败原因 |
| `所有上传通道均失败` | 第三方图床限流/故障，且平台通道不可用 | 看 `attempts` 明细：若平台通道写"跳过（未配置 API Key）"，引导用户配 Key 后用 `--host platform`，或稍后重试第三方图床 |
| 图床一返回 403「不允许直接调用API」 | 该图床做同源校验，缺浏览器指纹头 | 脚本已固定携带所需请求头；若仍 403，说明该图床做了更严限制 → 用 `--host thirdparty-b` 或 `--host platform` |
| 视频上传后链接打不开 | 图床一文档声明视频 ≤20MB；超限可能被拒/清理 | 裁剪或压缩后重试；可靠存放请用 `--host platform` |
| 中文文件名 | 部分图床/存储对非 ASCII 文件名处理不一致 | 脚本已自动把文件名转成 ASCII 安全形态（**三个通道都做**，v1.5.0 起平台通道也做），无需手动改名 |
| `上传完成但未返回文件访问地址` | 平台侧异常 | 稍后重试；持续失败请反馈 |
| `文件过大（… 上限 512 MB）` | 超过脚本的硬上限 | 先压缩/裁剪素材。超大文件几乎必然被图床拒绝，提前失败比传到一半失败更有用 |
| 提示「地址指向本机 / 内网，已跳过校验」 | 第三方响应或用户输入里的地址指向本机/内网 | 这是**保护**（不做本机探测，避免把用户机器当跳板）。换一个通道 `--host` 或换素材重试 |
| 上传"校验：通过"但生成时上游取不到图 | 历史上 403 被误判为"可用" | 已修复（v1.5.0）：**403 现在如实报为不可公开访问**；只有 405/416（对方不支持这种校验方式）才视为无法判定 |
| 生成时需要本地图片 | — | 直接用 `--ref-image ./path.png`（脚本自动上传），或先 `upload` 拿到地址 |
| **重要提醒** | 第三方图床非平台服务 | 提醒用户**不要上传敏感或重要数据**（可能被清理、链接失效） |

## 7. 耗时、超时与积分

| 现象 | 原因 | 处理 |
|---|---|---|
| 任务终态 `status=failed`，脚本打印「任务失败：<原因>」 | 平台判定失败，原因在终态响应体的 `error` 字段（已脱敏） | 把原因**中性转述**给用户（例：「这条提示词没通过平台审核，换一个再试」）；不要解释内部机制，也不要原样重试同一条请求。`task --id <ID>` 可再次读到同一原因（**退出码 1**） |
| `task --id` 输出"任务仍在处理中"但退出码是 1 | 该任务实际已是失败/取消/过期终态 | 已修复（v1.5.0）：终态失败会明确报失败原因并返回 1，**不会**再提示继续等待。看到 exit 1 就**不要**再 `wait` |
| 任务状态显示已完成，但没有任何结果地址 | 该次生成没有产出 | 脚本会返回 **exit 1** 并提示核对参数后重试。**不要**把它当成成功交付给用户 |
| 文本生成没有正文输出 | 响应里解析不出文本（模型可能返回了别的东西） | 脚本返回 **exit 1**，原始响应（已脱敏）打到 stderr 供排查 |
| 脚本打印「等待超时……**不是失败**」并给出任务 ID | 本地等待上限到了，平台任务仍在跑 | 用任务 ID 续等：`wait --id <ID> --type <类型>`；或 `task --id <ID>` 查一次。**不要**对用户说"生成失败" |
| 视频任务等很久仍没结果 | 视频典型耗时就是 1 分钟–1.5 小时 | 提前用区间沟通；长任务用 `--no-wait` 提交，拿到 ID 后再 `wait`，避免一条命令长时间占住终端 |
| 想调整等待上限 | 默认按类型给（图像 600s / 音频 1200s / 视频 5400s） | 显式加 `--max-wait <秒>`（**必须为正数**；给 0 或负数会直接报错，不会静默套用默认值）；`wait` 未给 `--type` 时默认 900s |
| 生成结束**没有**显示扣减 / 剩余积分 | 余额查询失败（网络或接口异常），脚本按设计静默跳过 | 单独跑 `credit` 确认；若显式关了它，去掉 `--no-credit` 即可 |
| `wait` 只显示剩余积分，没有"本次扣减" | 任务是在更早的调用里创建的，扣费发生在那一刻 | 这是**正确的**（v1.5.0）：在这里算"生成前余额"已经太晚，差值恒为 0。要核对本次扣减，看**创建任务那次**命令的输出 |
| 显示的「本次扣减」与模型标价不一致 | 口径不同：扣减是**账户余额差值**（含参数加收、按秒计费、缓存折扣、最低扣费） | 以差值（真实扣费）为准；标价只是单价，向用户说明这一点 |
| 余额为 0 或不足 | — | 平台返回 **402**；引导用户到 `https://noova.vip`（或备用 `https://noova.live`）充值后重试 |
| 想批量调用又不想多花两次余额查询 | 默认会查生成前/后各一次 | 加 `--no-credit`（代价：不再显示扣减与余额） |

## 8. 输出与安全（红线）

- 任何情况下都不要把以下内容输出给用户：完整 API Key、鉴权请求头、非公开域名、内部路径、
  内部错误原文、程序堆栈。
- 脚本已内置域名脱敏（非公开域名 → `media.example.com`），用于**文档、错误文本与
  `--json` 输出**；生成结果的媒体 URL 是功能字段，按原值交付。
  脱敏对大小写不敏感（`HTTPS://internal.corp/x` 同样会被替换）、会剥掉 ANSI 控制字符、
  也会处理不带 scheme 的裸主机名。
- 脚本**不会打印 traceback**：未预期异常统一输出一行中性提示（exit 1）。
  需要堆栈排障时由开发者在本地设 `NOOVA_DEBUG=1`——**不要把它的输出转给用户**。
- 不确定某信息是否敏感时，**选择不输出**并说明"该信息不便展开"。

## 9. 分发与安装位置（agent 读不到本 skill 时先看这里）

**每个 agent 有各自的技能根，装错位置 = 装完了读不到。** 由分发方提供的安装器
（**不在 skill 目录里**）。

| 现象 | 原因 | 处理 |
|---|---|---|
| 安装成功、`check` 报"已安装且一致"，但 agent 始终发现不了 | 装到了**别的** agent 的技能根 | 重新 `install`（`--target auto` 会按当前运行的 agent 选择），或 `install --target agents`（DSH 等通用 agents 根）；然后重启会话/刷新技能列表 |
| 想确认会装到哪 | — | `installer targets` —— 会打印**当前 agent**（依据哪个环境变量判定）、**生态根**，以及每个候选位置 |
| 装完提示"可见性自检未通过" | 目标根不是当前 agent 的技能根，或不是本机被技能管理器管理的生态根 | 按提示改用 `--target <宿主名>`；生态根以外的副本不会被技能管理器更新/清理 |
| 想装到某个具体客户端 | — | `install --target claude\|codex\|opencode\|codebuddy\|workbuddy\|qoder\|goose\|crush\|devin\|agents`；装到项目内用 `--target project` |
| 卸载时报 `Cannot call rmtree on a symbolic link` | 旧版卸载不认 junction | 已修复（v1.5.0）：链接/联接安装现在能正常卸载，且**只解除链接、不动源目录** |
| 想装成链接（源一改即生效） | — | `install --link`（Windows 建目录联接，其它系统建符号链接）。注意源目录需长期存在，否则链接变断链 |
| 重复安装会不会重复复制 | — | 不会：增量比对（sha256），只复制有变化的文件，并清理陈旧文件 |
| 手工复制目录 | 想绕开安装器 | **整个目录一起复制**，且必须复制 `scripts/noova_common.py`——少了它其余脚本无法导入。手工复制也容易把 `.noova/config.json`（内含 Key）一起搬走，**不建议** |
