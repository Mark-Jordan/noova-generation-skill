## 1.11.0 — 2026-10-14

**报价不再显示不可信的数字（含行为变更）**

用户口径：**不需要让用户预先知道会消耗多少积分**；若报价与真实扣费有冲突，一律以服务端
结算为准，此时**不显示任何金额**——生成结束后显示的账户余额变化，已经把该给的信息给全了。

- **只在服务端给出确定值时报价**：`credit_estimate_text` 现在仅当 `pricing.credits` 非空
  且 `exact: true` 时才输出「服务端权威价：N 积分」。
- **服务端给不出确定值时不给数字**：文案改为
  「本次消耗以生成结算为准（生成结束后显示账户余额变化）」。此前会输出
  「服务端未给出确定金额（…）；换算：100 积分 = 1 元」，其中的原因是**服务端的
  `note`**——那是给 agent 的接口指令（如「请核对参数取值后用 params 重新询价」），
  不是给用户的解释，现已**不再进入用户可见文案**。
- **移除本地复算兜底路径**：旧后端无 `pricing` 块、或询价失败时，原先会回退本地按
  `billing` + `surchargeRules` 复算并标注「按契约预估」。本地复算与服务端结算并不
  总是等价，既然冲突时以服务端为准，本地数字就不该上屏；该路径整体删除，
  `compute_credit_cost` 保留为内部工具函数（不再参与用户可见报价）。
- **数值层与文案层强制同源**：面板的 `credit_estimate.credits` 与 `credit_estimate_text`
  现在都由同一份服务端作答驱动；服务端给不出确定值时**两层同时留空**，
  不再出现「文案说以结算为准、数值层却顶一个本地数字」。
- `credit_estimate.note`（机器可读）保留服务端原因，供 agent 自行决策；
  它**不属于用户可见输出**。

> 影响面：仅用户可见文案与面板数值层，**不改请求契约、不改扣费逻辑、不发新请求**。
> 服务端给出确定值的模型行为不变。

## 1.10.0 — 2026-10-12

**参数依赖（选项分档）贯通面板 + 单值参数自动采用 + 两项计费修复（含对外契约变更）**

对外契约 `GET /api/models/params` 从本版起**不再下发 `line`（线路）**；同名模型一律
靠 `model` 编码区分。同一次变更里新增了参数依赖字段，修复了两个计费缺陷。

- **对外契约删 `line`**：该字段是运营手填自由文本、可能过期，且属内部运营语义。
  `models` / `model` / `params` / `form` 的全部出口（含 `--json`）同步删除 `line`、
  `line_label`、`line_legend`、`siblings[].line*`。同名模型在清单里改为加一行族标题
  「（同名 N 个，按编码区分）」，选择一律按 `model` 编码。
- **参数依赖贯通**：契约新增 `optionVisibleWhen`（**与 `values` 同序等长的平行数组**，
  无条件的项为 `null`）与字段级 `visibleWhen`。面板据此把「一次平铺 40 项」改为
  **按控制器取值分档**：`depends_on` / `option_groups` / `active_group`。
  未选控制器时**不隐藏任何一档**（与平台「控制器缺席则放行」一致），只是提示先选它能收窄。
- **单值参数自动采用**：`values` 恰好 1 个的参数不进面板，改为进 `preset_params`，
  由脚本自动写入请求体，必填校验同等对待（否则会出现「面板里没这个参数、请求前却报缺它」）。
  单值参数**仍参与可见性求值**——生产 4 个图像模型的比例分档依据的 `imageSize` 就是单值。
- **字段拓扑排序**：面板字段按「控制器在依赖项之前」排序，同级内保持必填在前；
  依赖悬空或成环时退回原顺序（不死循环、不丢字段）。
- **修复精确报价崩溃**（线上缺陷）：契约缺 `base` 键时 `_match_surcharge_charge` 误判为
  「取值非法」直接报错退出。4 个时长加收模型（`Seedance-2.0-mini-720p` 等）的精确报价
  全部受影响。现与平台服务端结算口径（基准值缺省按 `0` 计）及本文件近似价分支对齐：
  **缺 `base` 按 0 计**，只有 `multiplier` 缺失才是规则配置非法。
- **修 `exact` 规则取值比较**：改为与平台同口径的归一化比较（`5.0` == `5`），
  避免契约取值是数字、用户传 `"5.0"` 时本地判不命中而网关判命中（报价偏低）。
- **报价口径收紧**：`credit_estimate_text` 由「预计消耗 N 积分」改为
  「**按契约预估**：N 积分（…；真实扣费以服务端结算为准）」。文档明确唯一可核对的
  真值是生成结束后的「本次扣减（账户余额差值）」。
- 文档同步：`SKILL.md` 的参数面板一节、`references/parameters.md`（新增 §1.1 参数依赖）、
  `references/api-contracts.md`（删 `line`、加新字段与合成加收规则说明）。
- **服务端出数（2026-10-13 增补，同一未发布版本内）**：契约新增 `pricing` 块
  （`exact` / `credits` / `yuan` / `quotedParams` / `note`），并新增询价参数
  `GET /api/models/params?model=<编码>&params=<URL-encoded JSON>`。
  报价改为**优先引用服务端算好的 `credits`**（由服务端真实结算函数得出，即预扣额），
  调用方**不再按 `surchargeRules` 自己算**；`surchargeRules` 降级为**明细（非权威）**，
  保留用于对账与自建 UI。服务端给不出确定值（`credits: null`）时**如实说明原因，绝不编数字**；
  旧后端没有 `pricing` 块时回退本地复算，文案仍带「按契约预估」。
- `GET /api/models` 同步增补 `surchargeRules`；`priceOnce` 在文档中明确为**底价**（不含参数加收）。
- 文档同步：`references/api-contracts.md`（新增 §2.4.1 `pricing`、§2.3 增补字段）、
  `references/parameters.md` §5、`SKILL.md` 铁律 8 与报价两处说明。
- **修「报底价」**：契约自带的 `pricing` 是**不传参数**的默认组合价，
  对「本次参数」而言与底价等价。改前有两条路径把它当权威价用：
  ① `_announce_cost`（提交时报的价）根本不询价，`nano-banana-pro` 选 `imageSize=4K`
  时面板报 22、按下确认却报 20；
  ② `build_param_form`（面板）询价失败时回落到它，出现「数值层本地复算 22、
  文案层却说『**服务端权威价**：20 积分』」——用户看到哪个数字全凭 agent 挑哪一行。
  现统一：有 `surchargeRules` 的模型**必须**按本次参数询价，询价失败则**两侧都**回退本地
  复算并标注「按契约预估」；契约 `pricing` 不再参与「本次参数」的报价。
  无 `surchargeRules` 的模型价格与参数无关，契约 `pricing` 即真值，不发这次请求。
- **面板只有一个数字**：`credit_estimate`（数值层）与 `credit_estimate_text`（文案层）
  在服务端作答后同源；服务端明说给不出确定值时，数值层也**留空**（`credits: null`），
  不再「文案说给不出、数值层却顶一个本地数字」。
- **询价只带参与计费的参数**：`?params=` 是 GET，原本连提示词一并上传。
  实测 1200 字提示词编码后 `?params=` 为 10849 字节（500 字时 4549 字节），
  超 nginx 默认 8KB 请求头上限，服务端 414、询价静默失败、报价退化成「预估」；
  且用户创作内容会落进各级访问日志。现只送 `surchargeRules[].param` 命中的参数
  （与后端结算同一份规则，同一条件下编码后 25 字节）。
- **数值越界发请求前拦下**：原本只校验枚举 `values`，不校验 `min`/`max`。
  实测 `duration=999`（契约 max=15）本地照样报价 24975 积分，
  而平台会 400 拒单——等于先报一个不可能成交的价。现与枚举同一入口校验。
  判据只用契约 `min`/`max`，转不成数值的一律放行（交平台判，宁可少拦不误拦）。
- **人读输出不再列加收明细**：`models` / `model` / `params` / `form` 四处
  原本会在计价旁边逐条打印「↳ 加收：…」。用户要的是「一共多少」，
  不是费率分解；「按用量计价（见加收规则）」同步改为「按用量计价」，
  避免指向不再出现的内容。费率分解仍在 `billing.surcharge_rules` / `surcharge_text`
  这类**机器可读**字段里，`--json` 调用方不受影响。

> 影响面：对外契约字段增删（**纯增量新键 + 删除 `line`**，`schemaVersion` 保持 `1`，
> 旧客户端忽略未知键即可）；面板字段结构与报价文案变化；两个计费缺陷修复。
> **不改**请求契约（`POST /api/v1/invoke` 的字段名与取值口径未变）、不改扣费公式。
> 服务端出数相关的扣费改动在**后端**（结算接入 schema 派生加收规则），skill 侧只改报价来源。

## 1.9.3 — 2026-10-11

**枚举参数「取值」与「展示标签」混用（含行为变更）**

线上实测复现：图像模型的比例参数，契约 `values` 是像素串（`1280x720`），
`valueLabels` 才把它标成 `16:9`；而**参数面板的人读渲染只打印标签**，
于是照面板传 `--param aspect_ratio=16:9` 必然拿到 **HTTP 400**。

- **修 `_render_form` 的 `choice` 渲染**：改为 `取值（标签）` 输出，与 `params` / `model`
  同一口径。修复前面板会把**不可传**的标签当成可选值展示（`fixed` 分支一直打印 value，
  说明这是漏写而非设计）。
- **新增发请求前的取值预检**（`_ensure_param_values`，媒体与文本两条路径都接）：
  取值不在契约 `values` 里时**本地拒发**并列出合法取值，不再白跑一次往返。
  把标签当取值传时，提示直接给出「应传什么」。归一化口径与平台校验对齐
  （`5.0` == `5`、布尔转 `true`/`false`），避免误拦。
  保守放行：契约外参数名不管、`values` 为空的自由文本参数不管。
- **确定性错误不再建议重试**：`400` 等 4xx 不再透传网关无差别返回的 `Retry-After`
  （实测 `401` 也带同一个头，与「可否恢复」无关）。修复前取值非法的 400 会附
  「建议 60 秒后重试」，把「改参数」误导成「等一等再试」。`429` / `5xx` /
  平台配额 / `408` / `425` 仍保留重试提示。
- 文档同步：`SKILL.md` 参数面板一节与 `references/parameters.md` 明确
  「`value` 才是可传值，`label` 仅供展示」，并给出图像/视频模型取值形态不同的提醒。
- 回归用例：`test_noova_regressions.py::EnumValueVsLabelTest`（9 条）+
  `DeterministicErrorMustNotSuggestRetryTest`（5 条）。

> 影响面：仅展示层与发请求前的本地校验，**不改请求契约**。此前成功传对的调用
> 行为不变。

## 1.9.0 — 2026-10-10

**官方双域名支持（noova.vip 主域名 / noova.live 备用域名）**

- 官方域名从单一 `noova.vip` 扩为 `noova.vip` + `noova.live`（`noova_common.OFFICIAL_HOSTS`）：
  两者承载同一套对外 API，粘贴解析可信、地址守卫放行、脱敏白名单保留，**同等对待**。
- `www.` 变体统一归一到 apex（`www.noova.vip` → `noova.vip`，`www.noova.live` → `noova.live`）：
  避免同一站点两种写法在可信域判定与脱敏白名单里漂移；归一**不改变 scheme**，
  `http://www.noova.vip` 仍被明文拦截拦下。
- 修复既有缺陷：`is_local_host()` 对 `www.dev.example.com` 这类写法漏判开发前缀——
  DNS 解析失败时守卫会按「离线」放行，属于安全口子。现在剥离 `www.` 后再判定前缀。

> 升级说明：此前配置为 `noova.vip` 的用户不需任何操作；想改用备用域名的用户用
> `noova_key.py base https://noova.live` 切换即可（后续请求与脱敏自动跟随）。
